L'architecture du site Surprisez-Vous

Vitrine, espace pro et back-office sur une seule application Next.js, adossée à Firebase et alimentée par l'ERP à travers Google Drive. Cette page montre comment les données circulent — du classeur métier jusqu'à la fiche produit.

Vue d'ensemble

Le site ne parle jamais directement à l'ERP : Google Drive sert de sas. Les exports CSV y sont déposés, les Cloud Functions les ingèrent dans Firestore, et l'application Next.js sert les trois publics depuis son cache serveur.

Zones de l'application

Une seule application, quatre territoires. Les groupes de routes de l'App Router ((public), admin, pro) portent chacun leur layout, leur garde d'authentification et leur navigation.

Vitrine publique

18 pages

Accueil animé, catalogue par rayons piloté par les attributs, fiches produit avec déclinaisons, showroom three.js, carte des revendeurs, tunnel d'inscription pro.

Espace pro

9 pages · Auth

Back-office admin

16 pages · claim

Catalogue et attributs, CRM (~3 800 clients servis par la fonction de cache), commandes, tarifs, marketing, statistiques, pilotage des syncs — et l'éditeur qui modifie la vitrine en place, dans la page.

API interne

5 routes

Invalidation du cache serveur par tag, relais vers la fonction de cache, warmup, aides aux tests e2e. Les routes sensibles exigent le secret CACHE_SECRET.

POST /api/revalidate/api/cache/[collection] /api/cache/patchGET /api/warmup/api/e2e/*

L'éditeur de contenu en place

Depuis /admin/editeur, l'admin voit la vitrine en iframe ((editor-preview) fournit des rendus isolés du header et du footer) et clique directement sur les textes, images et blocs à modifier. Les composants components/editable/ persistent dans Firestore, et l'iframe dialogue avec l'éditeur par postMessage (iframe-edit-context).

Le référentiel d'attributs, du classeur à la fiche produit

Le classeur Google Sheets est la source de vérité métier : c'est là que se décrivent univers, occasions, thèmes, couleurs et matières. La jointure avec l'ERP se fait sur ref (classeur) ↔ pdt_reference (ERP).

Mode local — zéro lecture facturée.

Avec SV_LOCAL_DATA=1, toute la couche lib/firestore/ lit des fixtures JSON dans .local-data/ au lieu de Firestore. Les fixtures viennent de npm run local:data (snapshot réel) ou -- --demo (jeu de démonstration hors ligne). On développe et on démontre sans toucher au quota.

Stratégie de cache

L'objectif : qu'une visite publique ne coûte (presque) aucune lecture Firestore. Trois niveaux s'empilent, du serveur au navigateur.

Sécurité

Le rôle admin n'est pas un champ en base : c'est un custom claim Firebase, posé automatiquement et vérifié partout — règles Firestore comme layouts.

  • Claim admin automatique — le trigger setAdminClaim pose le custom claim à l'écriture de users/{uid} ; app/admin/layout.tsx et les règles s'appuient dessus.
  • Règles versionnées — firestore.rules (catalogue lisible publiquement, écritures réservées admin, données clients cloisonnées par uid), storage.rules, database.rules.json.
  • Inscription pro filtrée — reCAPTCHA v3, demandes stockées dans pro-requests en attendant la validation admin.
  • API à secret partagé — /api/cache/* et /api/revalidate exigent CACHE_SECRET, défini côté App Hosting et Functions.
  • Droit à l'oubli — l'extension delete-user-data purge les données à la suppression d'un compte ; la vitrine expose /demande-oubli.

Tests & déploiement

Tests

  • Unitaires — Vitest + Testing Library : 47 tests, mocks Firebase dans __mocks__/.
  • E2E — Playwright, 5 suites (public, pro, admin, auth), exécutables contre l'émulateur Firebase avec garde anti-prod.
  • Manuel — cahier de test versionné dans docs/CAHIER-DE-TEST.md.

Déploiement

  • Site — Firebase App Hosting, build au push : 1 CPU / 512 Mio, 0→4 instances (apphosting.yaml).
  • Backend — firebase deploy --only functions, --only firestore:rules, --only storage, --only database.
  • Émulateurs — Auth (9099) + Firestore (8080) pour le développement et les e2e.
Workflow git : feature/<sujet> → PR vers develop → PR develop → main. Le détail versionné vit dans docs/ARCHITECTURE.md.
